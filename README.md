# 飲食.Pi (Inshoku.Pi)

Pi・暗号資産で支払える飲食店を、現在地から検索してGoogleマップで経路案内するアプリ。
Pi Browserと通常のブラウザの両方で動作します。

## いちばん大事な前提

Google Places / Google Maps には「暗号資産で支払い可能かどうか」というデータは存在しません。
なのでこのアプリの本体は **地図表示ではなく、店舗データの収集** です。3つの入力経路を用意しています。

| 経路 | 誰が | コスト | 掲載時の信頼度バッジ |
|---|---|---|---|
| 店舗自己登録 | 店舗オーナー | Pi払い(掲載料 3π、`register.js`内`LISTING_FEE_PI`で変更可) | 🟠 自己申告(決済済) |
| 運営が手動登録 | アキノリさん(管理画面) | 無料 | 🟢 運営確認済み |
| ユーザー投稿 | 誰でも | 無料(審査あり) | ⚪ コミュニティ投稿 → 管理画面で承認すると🟢に昇格 |
| 外部ディレクトリから自動取込 | サーバー(自動 or 管理画面ボタン) | 無料 | 🔵 外部データ取込 |

## 地図と経路について(無料・課金なしの設計)

ユーザー数が増えても運営コストが青天井にならないよう、地図表示と「経路を見る」はどちらもGoogleの有料APIを一切呼び出さない設計にしています。

- **地図の表示**: [Leaflet](https://leafletjs.com/)(JSライブラリ)+ [OpenStreetMap](https://www.openstreetmap.org/)のタイル画像を使用。APIキー不要・クレジットカード登録不要・利用回数による課金の仕組みそのものがありません。CSSで色調をアプリのダークテーマに合わせています(`assets/style.css`の`.leaflet-tile-pane`)。
- **「経路を見る」ボタン(アプリ内)**: 現在地とお店を結ぶ直線をLeaflet上に描画するだけです(どこかのAPIに問い合わせているわけではないので、これも無料・無制限です)。実際の道なりのルートではなく、あくまで「だいたいどの方向に・どれくらいの距離か」を見るためのものです。
- **「Google Maps ↗」ボタン**: これはAPI呼び出しではなく、ただのURLリンク(`https://www.google.com/maps/dir/?...`)です。タップした人のスマホ・PCで、その人自身のGoogleマップアプリ/サイトが開いて実際のナビが始まります。何人がこのボタンを押しても、運営側に課金が発生することはありません。

将来、道なりの正確なルート(徒歩○分、道順の折れ線など)をアプリ内に表示したくなった場合は、[OSRM](https://project-osrm.org/)(オープンソースの無料ルーティングエンジン、自前ホスティングも可)などGoogleに依存しない選択肢があります。その際は`assets/app.js`の`dirBtn`のクリック処理を差し替える形になります。

## 自動取込機能(既存の暗号資産対応店を見つけて自動追加)

「Pi Network内、通常のブラウザ内で登録済みの店舗を自動で見つけて追加する」ための仕組みとして、
`server/importers/` に取込モジュールを用意しました。ただし2つの経路で状況が大きく異なります。

### 通常のインターネット側: Coinmap連携(実装済み・動作します)

[Coinmap](https://coinmap.org) は OpenStreetMap のタグ(`payment:bitcoin=yes` 等)を元にした、
**無料・認証不要・ODbLライセンスの公開API** です。実在する仕組みなので、そのまま使えます。

- `server/importers/coinmap.js` が `https://coinmap.org/api/v1/venues/` を叩いて、
  指定した緯度経度・半径内の飲食系ベニュー(restaurant/cafe/bar/bakery等)だけを取り出します。
- 管理画面(`/admin.html`)の「外部ディレクトリから自動取込」フォームから、エリアを指定して手動実行できます。
- 完全自動運用したい場合は `.env` の `IMPORT_REGIONS`(監視したいエリアのJSON配列)と
  `IMPORT_INTERVAL_HOURS`(何時間おきに再取込するか)を設定すると、サーバー起動時にスケジューラが立ち上がり、
  指定間隔で自動的に新規ベニューをチェックして追加します。
- 取込直後は既定で「審査待ち」キューに入ります(`IMPORT_AUTO_APPROVE=true` で即時公開に変更可)。
- **重要な制約**: CoinmapはPi Networkを認識していません。取込したデータの決済手段は基本的に `BTC` タグになります
  (Piでの支払いに対応しているかどうかは分かりません)。あくまで「暗号資産全般に理解のあるお店」を発見する入り口として使ってください。
- Coinmapのデータを表示する際は OpenStreetMap への帰属表示が必須です(検索画面フッターに記載済み)。

### Pi Network側のディレクトリ(Map of Pi 等): 現時点では未対応

Map of Pi や Piketplace のような、Pi専用の店舗ディレクトリ自体には、外部から使える公開APIが
今のところ存在しません(Map of Piはソースは公開されていますが、それは特定チームが運用する
自前のバックエンドであって、誰でも叩ける公開データフィードではありません)。UIを直接スクレイピングする
方法は壊れやすく規約上のリスクもあるため、あえて実装していません。

`server/importers/pi-directories.js` に、将来ここへ本物の連携を差し込むための空の関数だけ用意してあります。
現実的な対応としては次の2つです。

1. Map of Pi / Piketplace のチームにAPI連携やデータ共有を打診する(同じPiエコシステムで開発しているので相談の余地はあります)
2. それまでは、それらのアプリで見つけた店舗を `/admin.html` の「手動で店舗を追加」から運営確認済みとして登録する
   (これはもともと用意していた「運営が手動で調査・入力する」経路そのものです)

自己申告は「支払った」ことの確認であって「本当にPiで支払えるお店か」の確認ではありません。
そこはUI上でバッジを分けて誠実に表示し、運営確認済みと混同されないようにしています。

├── assets/
│   ├── style.css         共通デザイントークン
│   ├── i18n.js           日本語/英語の切り替え辞書
│   ├── currencies.js     対応通貨リスト(Pi/BTC/ETH/USDT/USDC/その他)

│   ├── importers/

├── package.json

## セットアップ

1. 依存パッケージのインストール
   ```
   npm install
   ```
2. `.env.example` を `.env` にコピーし、値を埋める
   - `PI_API_KEY`: Pi Developer Portal のアプリ設定から取得
   - `ADMIN_TOKEN`: 管理画面用のパスワード代わり(長いランダム文字列を推奨)
3. 地図はGoogle Maps APIではなく **Leaflet + OpenStreetMap** を使っています。APIキーの取得も課金設定も一切不要です(詳しくは下の「地図と経路について」を参照)
4. Pi Developer Portal でアプリを登録し、ドメインを紐付ける(`app-3911` の枠を流用する場合はスラッグ・ドメイン設定を確認)
5. 起動
   ```
   npm start
   ```
   `http://localhost:3000` で確認できます。管理画面は `/admin.html`。

## デプロイ時の注意

- `server/` フォルダごとデプロイすればNode環境でそのまま動きます(Vercel/Renderの場合はExpressアプリとして、VPSの場合は`pm2`等で常駐)。
- 静的ファイルだけを別ホスティング(Pi Browser用の静的配信)に置く場合は、API呼び出し先(`fetch("/api/...")`)を実際のバックエンドのフルURLに書き換えてください。
- `server/data/restaurants.json` はファイルベースなので、サーバーレス環境(再起動でファイルシステムが消える環境)では永続化されません。本番運用前にPostgres等の実データベースに置き換えることを推奨します(`server/db.js` の関数群がその置き換え箇所です)。

## セキュリティ・信頼性に関する既知の課題(本番化前に対応すべき点)

- `admin.js` のトークン認証は簡易的な共有パスワードです。複数人で管理画面を使うなら、きちんとしたログイン機能に置き換えてください。
- `payments.js` の `complete` ルートは、Pi APIから支払い内容(金額・メタデータ)を再取得して照合する処理をコメントで示していますが、実装は省略しています。本番前に必ず追加してください(クライアントが送ってきた`restaurant`データを無条件に信頼しない)。
- 位置情報(緯度・経度)はクライアントの自己申告です。悪意のある登録(実在しない店舗、誤った場所)を弾く仕組みが今はコミュニティ投票と運営レビューだけなので、規模が大きくなったら住所とのつき合わせ(ジオコーディング検証)などを足すと安全です。

## 決済と規制についての設計方針

このアプリ自体は「食事の代金」を仲介しません。お客さんが実際にPiや暗号資産で支払うのは、お店とお客さんの間で直接行われます(現地でQRコードを見せる、ウォレットで送るなど、アプリの外の話)。アプリ内でPi決済が発生するのは「店舗の掲載料」だけです。この切り分けは、Casino.pi Academyで「教育コンテンツの解放にのみPi決済を使い、賭け金のやり取りはしない」とした設計方針と同じ考え方です。
